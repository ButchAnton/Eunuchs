## Machine and boot

*Details: [Boot and platform](subsystems/01-boot-and-platform.md).*

QEMU's `virt` board: RV64GC harts, 128 MiB of RAM at `0x80000000`, a 16550 UART, a PLIC, a CLINT, a goldfish RTC, the `sifive,test0` exit device, and eight virtio-mmio slots. OpenSBI runs in M-mode and starts the kernel in S-mode at `0x80200000`, on a randomly chosen hart, passing the hart id and a device tree.

1. **`boot.S`.** Clears BSS. Builds an early page table: an identity gigapage for the running code, plus 64 GiB of direct map at `KERNEL_BASE` (`0xffffffc000000000`). Turns on paging and jumps to the linked (high) address. Points `tp` at `cpus[0]` and calls `kmain`.
2. **`kmain`** (`core/main.c`), in order:
   - per-CPU setup and the trap vector;
   - device-tree parsing (`fdt.c` fills `struct platform_info`), the console and the command line;
   - the page allocator, the real kernel page table (`vm_init`), slab, tracing, the scheduler, processes, the PLIC, the TTY, the timer;
   - the other harts (`smp_init`), the profiler if requested;
   - then it starts `kinit` and becomes cpu0's idle thread.
3. **Other harts.** Started with SBI HSM at `secondary_entry`, they reuse the early page table for one instruction, switch to the kernel page table, take their idle thread's stack, and enter their idle loop.
4. **`kinit`.** Brings up the disks (`blk_init`), mounts the filesystems (`vfs_init`: `/` from the disk labelled `root`, `/home` from the one labelled `home`) and starts the network (`net_init`). Then it runs the kernel tests (`ktest`), the user tests (`utest`), or `/bin/init`, which runs the shell.

The kernel is linked twice: the first link's symbols become a table (`.ksyms`, generated by `tools/gen_ksyms.py`) embedded in the second. This is how panics, `ps` and the profiler name functions without a debugger.

Watch: the boot log (`dmesg`), the `plat` and `dtb` monitor commands, `eu-platform` in GDB, and the boot option `break` to stop in the monitor early.

## Memory

*Details: [Memory](subsystems/02-memory.md).*

**Layout (Sv39):**

| Range | Contents |
|---|---|
| `0x0000000000010000 – 0x0000004000000000` | User space. Programs at `0x10000`, heap after them, `mmap` area, 8 MiB stack at the top. |
| `0xffffffc000000000 + PA` | Direct map of all RAM and the MMIO devices that were `ioremap`ped. |
| `0xffffffc080200000` | The kernel image, inside the direct map, mapped W^X section by section. |
| `0xffffffe800000000` | Kernel stacks: 16 KiB of stack above a 16 KiB unmapped guard, in 32 KiB slots. |

NULL, OpenSBI's memory and any MMIO not explicitly mapped are unmapped, so stray pointers fault with a precise report.

**Physical pages:** a buddy allocator (`mm/buddy.c`, orders 0–10) with a `struct page` for every frame (`pmm.c`). Each frame records flags, a reference count (for shared copy-on-write pages) and its allocation and free sites. Freed pages are filled with `0x6b` and checked when reused.

**Kernel heap:** `kmalloc`/`kzalloc` (`mm/slab.c`) use size-class caches with redzones, `0x5a`-filled new objects, FIFO free lists (to delay reuse) and allocation sites. Allocations over 2 KiB take whole pages.

**Page tables:** `vmm.c` handles the kernel page table, `ioremap` and lookups. Changes to the kernel page table are serialized by a lock. Removing a kernel mapping needs a **TLB shootdown** (IPI every CPU, wait for acknowledgements), so freed kernel stacks are cached while still mapped. Process page tables copy the kernel's top-level entries (`vm_sync_kernel`); a kernel fault on a newly added top-level entry is fixed lazily.

**User memory** (`uvm.c`): an `mm` is a page table plus a sorted list of VMAs (ELF segments, heap, `mmap` areas, stack).
- Pages are allocated on first touch (`uvm_fault`).
- `fork` shares pages copy-on-write (`PTE_COW`, reference counts).
- `mprotect` changes a range's permissions (splitting VMAs, never rwx); adding execute runs `fence.i` on every hart.
- Walks over page tables skip empty tables whole.
- Kernel code touches user memory only through `copy_from_user`/`copy_to_user` (`uaccess.S`). Those set `SUM` only for the copy and register their instructions in the exception table, so a bad pointer returns `EFAULT` instead of a panic.

Watch: `meminfo`, `pt`, `v2p`, `page`, `slab`, `slab leaks`, `heapcheck`, and `vm <pid>` in the monitor; `/proc/meminfo`, `/proc/slabinfo` and `/proc/<pid>/maps`.

## Traps, interrupts and system calls

*Details: [Traps, interrupts and system calls](subsystems/03-traps-interrupts-syscalls.md).*

`trapentry.S` is the single trap vector:
- **Coming from user mode:** `sscratch` holds the CPU's `struct cpu`. The full register frame is saved at the top of the thread's kernel stack (`thread_user_tf`).
- **Coming from the kernel:** the frame goes on the current stack. An overflow check (the guard bit in `sp`) switches to a per-CPU emergency stack if needed.

Every frame also gets a fake frame record and CFI, so `bt` (ours and GDB's) walks through traps. On return to the kernel the frame's `tp` is replaced by the live one, because the thread may have moved to another CPU.

`trap.c` dispatches:
- **interrupts:** the timer (scheduler tick, watchdog, profiler samples), the PLIC (device interrupts, all routed to cpu0), and software interrupts (IPIs);
- **system calls:** `ecall` with Linux RISC-V numbers. The table is the `SYSCALLS` X-macro in `lib/include/uapi/syscall.h`, shared with libc, `strace` and the trace tools;
- **user faults:** demand paging, copy-on-write, turning on floating point at a thread's first FP instruction, or a signal with a diagnosis;
- **kernel faults:** the exception table, else a panic.

Before returning to user mode the kernel may reschedule, delivers pending signals and restarts interrupted system calls.

Watch: `strace`, `traps` and `irq` in the monitor, `/proc/interrupts`, and the `syscall` and `irq` trace groups.

## Threads, scheduling and SMP

*Details: [Threads, scheduling and SMP](subsystems/04-threads-scheduling-smp.md).*

**Threads** (`core/sched.c`): each has a 16 KiB guarded kernel stack and a saved context (`switch.S`). A process has exactly one thread.

**Scheduler:**
- One round-robin run queue shared by all CPUs, under `sched_lock`, which stays held across the context switch.
- Timer ticks (100 Hz) preempt threads that were running with interrupts enabled.
- A busy CPU that makes a thread runnable wakes an idle CPU with a reschedule IPI.
- `kthread_bind` pins a thread to one CPU.

**Rules that make SMP work:**
- Per-CPU data hangs off `tp` (`percpu.h`).
- `current` is a single `ld 0(tp)`, so preemption can't split it.
- Code running with interrupts on never keeps a `struct cpu *` across a point where it could be preempted (and so migrate). The scheduler re-reads its CPU after every switch.

**Synchronization:**
- **Spinlocks** disable interrupts and record their owner and site. While spinning they also answer stop and TLB-flush IPIs.
- **Mutexes**, **semaphores** and **wait queues** handle sleeping (`sync.c`). `wait_event`/`wait_event_interruptible` re-check their condition after every wakeup. Multi-source waits (`poll`, `netd`) mark the thread sleeping *before* checking anything (`set_current_sleeping`, `schedule_until`).
- **lockdep** (`debug/lockdep.c`) records the order in which lock classes are taken and reports any cycle the first time it becomes possible. A hung-thread detector reports mutex waits over 30 s, and a watchdog panics if a CPU stops taking timer interrupts.

**IPIs** (`arch/riscv/smp.c`): resched, TLB flush, stop. "Stop the world" parks every other CPU (from an interrupt, or from inside a spin loop) for the monitor and for panics, recording where each one was.

Watch: `ps`, `sched`, `cpus`, `cpu <n>`, `locks` and `lockdep` in the monitor; `/proc/threads`, `/proc/cpus`; GDB `eu-ps` and `eu-cpus`; Perfetto traces with one track per CPU.

## Processes

*Details: [Processes and signals](subsystems/05-processes-and-signals.md).*

`proc/proc.c` handles the process list, `fork`, `exec`, `exit` and `wait4`.

**`exec`:** reads the whole program from the filesystem into a reference-counted image (also used to symbolize user backtraces). The ELF loader (`elf.c`) maps the segments, and argv and envp go on the new stack. The old address space goes away only once the new one is complete.

**`exit`:** releases the address space and files, reparents children to init, becomes a zombie and notifies the parent, all under `proc_lock`. `proc_lock` protects the process list, parent and child links, process state, signal state, process groups, and the `mm`/image/thread pointers. Holding it keeps any process from being freed, which `kill` and procfs rely on.

**Signals** (`signal.c`): Linux numbers and `sigaction` semantics. Handlers run on a signal frame on the user stack, returning through `rt_sigreturn`. Stop and continue follow job-control rules, and interrupted system calls are restarted (`ERESTARTSYS`) or fail with `EINTR`.

**Credentials** (`cred.c`): real, effective and saved uid/gid, permission checks in the VFS, setuid executables, umask.

**User space** (`user/`): `crt0.S`, system call stubs and a small libc (buffered `FILE` stdio, `printf`/`scanf` with floating point, a malloc with debugging checks, `math.h`, `time.h` with `strftime`, `setjmp`, POSIX regular expressions, sockets, `poll`/`select`, termios). User programs are built for RV64GC and may use floating point; the kernel, built without it, saves a thread's FP registers only once the thread has used them. `init` runs the shell, `esh` (also `/bin/sh`): a zsh-like language (functions, arrays, `[[ ]]`, here-documents, zsh's expansion rules), job control, and a line editor with syntax highlighting, autosuggestions, history search and Tab completion ([12-shell.md](subsystems/12-shell.md)). `eutils` is one binary behind 32 command names (`echo`, `cp`, `kill`, `profile`, `crc32`, ...). `edit` is a text editor that runs as `vi`/`view` or `emacs`/`em` depending on its name.

**The native toolchain** ([13-toolchain.md](subsystems/13-toolchain.md)): `/bin/tcc` is TinyCC, built by GCC against the libc; a host build of the same compiler (`build/tcc/xtcc`) makes its runtime library. The image carries a sysroot (`/usr/include`, `/usr/lib/{crt1.o,libc.a}`, `/usr/lib/tcc/libtcc1.a`), a small POSIX `make`, and the sources of every program in `/usr/src`, so Eunuchs can rebuild its own user space. `tcc -run` compiles into memory and relies on `mprotect` to turn the generated code executable without breaking W^X.

**The debugger** ([14-debugger.md](subsystems/14-debugger.md)): the kernel implements `ptrace` (`proc/ptrace.c`): a traced process stops whenever a signal is about to be delivered to it, including the SIGTRAP from an `ebreak` or after `exec`, and its tracer reads and writes its registers and memory and resumes it. `db` (`user/bin/db/`) is a gdb-like debugger on top: software breakpoints and single-stepping (RISC-V has no trace trap, so it decodes the next instruction), frame-pointer backtraces, a DWARF 4/5 reader for line tables, types, scopes and variable locations, an expression evaluator and an RV64GC disassembler. A user `ebreak` is now a SIGTRAP rather than an entry into the kernel monitor (`dbg_break()` still enters it).

Watch: `procs`, `ubt <pid>`, `vm <pid>`, `files <pid>` and `strace <pid>` in the monitor; `/proc/<pid>/{status,maps,fds,stack,ustack}`; a fault report for every crashed program.

## Files

*Details: [Filesystems](subsystems/06-filesystems.md).*

The **VFS** (`fs/vfs.c`) has an in-memory inode cache (each inode with a mutex), path lookup with mount points (`/home`, `/dev`, `/proc`) and permission checks. **File objects** (`file.c`) hold a reference count, an offset and flags. Each process has a 32-entry descriptor table with close-on-exec flags.

**efs** (`fs/efs.c`, layout in `include/efs_format.h`):

| Blocks | Contents |
|---|---|
| 1 | superblock |
| log | write-ahead log: a header block plus data blocks |
| inodes | the inode table |
| bitmap | the free-block bitmap |
| data | file and directory blocks |

- 4 KiB blocks and 1024 inodes. Each file has 12 direct blocks plus a single- and a double-indirect block.
- Directories are files of fixed-size entries.
- Every change happens inside a transaction (`log.c`, re-entrant per thread). The transaction is written to the log, committed, then installed. Recovery at mount replays committed transactions and drops incomplete ones, so a power failure at any point leaves the filesystem consistent (the `fs.crash=` boot option simulates one).
- **Buffer cache** (`bcache.c`): 128 buffers, each with its own mutex.
- **mkfs/fsck** (`tools/mkfs/`): a host program that builds `build/fs.img` (and `home.img`, the persistent `/home` disk), with a volume label in the superblock, and checks images.
- **Several disks:** the buffer cache is keyed by (disk, block) and each mounted efs has its own log, so `/` and `/home` live on separate virtio disks.

**Other file types:**
- **pipes** (4 KiB rings);
- **devfs** (`/dev/console`, `null`, `zero`, `kmsg`, `disk0`, `disk1`, `tty`);
- **procfs**: text files generated on open from the same print functions the monitor uses.

`poll.c` implements `ppoll` for every kind of file.

Watch: `mounts`, `bcache`, `icache`, `pipes` and `blk` in the monitor; `make fsck`; the `blk` and `fs` trace groups; `/proc/mounts`.

## Network

*Details: [Networking](subsystems/08-networking.md).*

Packets live in **netbufs**: 2 KiB with 128 bytes of headroom, so each layer prepends its header without copying.

**Receiving:** the driver's interrupt handler (or the loopback interface) queues packets for the **`netd`** thread. `netd` runs the protocols with **`net_lock`** (one mutex for all network state) held, and also drives the protocol timers.

**Sending:** happens in the calling thread.

**Protocols:**
- **Ethernet and ARP** (`ether.c`): a 32-entry cache, with packets waiting on an unresolved address.
- **IPv4** (`ipv4.c`): routing between `lo`, the eth0 subnet and the gateway; no fragmentation.
- **ICMP:** echo, plus raw sockets for `ping`.
- **UDP** (`udp.c`).
- **TCP** (`tcp.c`): handshake, sliding windows, out-of-order reassembly, RFC 6298 timers with Karn's rule, fast retransmit, Reno congestion control, zero-window probing, FIN/RST/TIME_WAIT, listen backlogs, and connections that finish closing after their socket is gone. `tcp.c` depends only on `net.h`, so `tests/host/test_tcp.c` runs it natively against a simulated lossy link.

**Sockets** (`socket.c`): stream, datagram and raw sockets are files. Blocking calls wait on a per-socket counter bumped by every wakeup, and `poll` reads a cached readiness mask.

With QEMU's user-mode network the guest is 10.0.2.15 and the Mac is 10.0.2.2. `make run` forwards Mac ports 8080, 2323 and 5555 to the guest's `httpd`, `rshd` and `echod`.

Watch: `/proc/net/*`, `net` and `netstat` in the monitor, `log=net:debug` for a line per packet, `build/net.pcap`, the `net` trace group, `eu-net` in GDB, and `net.drop=` to inject packet loss.

## Debugging infrastructure

*Details: [Debugging internals](subsystems/09-debugging-internals.md).*

Built alongside everything else, and described in [DEBUGGING.md](DEBUGGING.md):

- **Logging:** a printk ring with per-subsystem levels.
- **Symbols and backtraces:** symbolized backtraces through traps and into user space, and panics that report all CPUs.
- **Monitor:** the kdb-style monitor (`debug/monitor.c`), which stops the world.
- **Trace:** a per-CPU event ring (`debug/trace.c`) exported to Perfetto.
- **Profiler:** sampling every CPU (`debug/profile.c`), exported as reports and flamegraphs.
- **Lock checking:** lockdep and the watchdogs.
- **GDB:** helpers in `tools/gdb/eunuchs.py`.
- **Tests:** kernel unit tests (`KTEST`, `debug/ktest.c`), user tests (`user/bin/utests.c`), the stress program, the scenario runner (`tools/run_tests.py`), host tests, and `make ci`.
- **Replay:** deterministic record/replay with reverse debugging, through QEMU.
